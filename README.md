# 黔行 · 贵州景区导览

一个不依赖构建工具的纯静态前端项目，用于按等级展示贵州旅游景区，并提供注册、登录、景区收藏与评分评价功能。前端具备 **在线 / 离线双模式**：后端可达时使用 Spring Boot + MySQL 的真实数据；后端不可达（未启动服务，或直接双击 HTML 以 `file://` 打开被 CORS 拦截）时，自动降级为浏览器本地存储，无需任何环境即可完整体验全部功能。

## 功能

- **按等级浏览景区**：按 5A、4A、3A 分组展示，每个景区包含名称、所在地、简介、评分、标签、最佳季节、参考票价等信息。
- **搜索与筛选**：支持按景区名称、城市、简介、标签搜索，并可单独筛选某一等级。
- **景区详情页**：点击卡片跳转到独立页面 `spot.html?id=<景区ID>`，查看完整介绍、不可错过的亮点、建议时长和地址；页面横幅使用该景区的实景照片。
- **注册 / 登录**：在线模式账号信息持久化到后端 MySQL（`tourism_database`），密码以 BCrypt 哈希存储；离线模式账号保存在浏览器本地存储，登录状态跨页面共享。两种模式下登录态与会话隔离。
- **后台管理**：管理员可在 `admin.html` 查看全部注册用户，封禁普通用户（必须填写封禁理由，该理由会展示给被封禁用户）或解封；管理员账号不可被封禁，也不能封禁自己。
- **收藏景区**：登录后可收藏 / 取消收藏，未登录时点击收藏会提示先登录。
- **评分与评价**：登录后可在景区详情里打 1–5 星并写下最多 200 字的评价，同一账号对同一景区可修改或删除；未登录只能查看。卡片与详情的评分会按“景区基础评分 + 本机账号评价”实时汇总。
- **我的收藏**：收藏列表按最近收藏排序，支持取消收藏与查看详情。
- **全屏轮播首屏**：首页顶部为铺满整个视口的轮播（黄果树瀑布、梵净山、遵义会议会址、赤水丹霞、小七孔、织金洞，加上品牌页共 7 屏），每 3 秒自动切换，支持左右箭头手动切换；导航悬浮在图片上，页面滚动后自动转为实色底。
- **响应式布局**：适配桌面、平板与手机。

## 快速开始

本项目有两种运行方式，**双击打开**最简单，无需安装任何环境。

### 方式一：双击打开（推荐，零环境）

直接双击项目根目录下的 `index.html`，用浏览器打开即可。

- 无需启动后端、无需安装 MySQL / Java / Python，也不需要敲任何命令。
- 检测到后端不可达（未启动服务，或 `file://` 双击被浏览器 CORS 拦截）时，前端自动降级到**离线模式**：注册、登录、收藏、评价、后台管理全部功能照常可用，数据保存在当前浏览器的本地存储中。
- 离线模式首次运行会自动播种内置景点数据与默认管理员账号（`admin` / `admin123`）。
- 数据范围：离线数据仅存于当前浏览器，清除浏览器数据或更换浏览器会重置；在线模式与离线模式的数据相互隔离。
- 适用场景：课程演示、发给老师 / 同学直接预览。

### 方式二：完整全栈运行（可选，真实服务端数据）

同时启动**后端服务**（端口 8081）和**前端静态服务**（端口 8080），登录注册与后台管理将使用 MySQL 中的真实数据。

#### 1. 启动后端（端口 8081）

`backend/target/travel-backend.jar` 已预编译好，无需自己打包，直接运行即可：

```powershell
cd backend
java -jar target\travel-backend.jar
```

> 若修改过后端源码，可重新打包：`mvn -q -DskipTests package`（需本机安装 Maven）。

后端首次启动时会**自动创建** `tourism_database` 数据库及所需表，无需手动建库。只需保证 MySQL 服务已启动，并让后端知道你的 MySQL 账号密码（二者任选其一）：

- 设置环境变量后再启动（推荐，不改源码）：
  ```powershell
  $env:DB_USERNAME='root'       # 你的 MySQL 用户名
  $env:DB_PASSWORD='你的密码'   # 你的 MySQL 密码
  java -jar target\travel-backend.jar
  ```
- 或直接编辑 `backend/src/main/resources/application.yml` 中的 `username` / `password` 默认值，重新打包运行。

#### 2. 启动前端静态服务（端口 8080）

在项目根目录执行：

```powershell
python serve.py
```

然后访问 <http://127.0.0.1:8080>。

> 也可用任意静态服务器托管项目根目录（如 `npx serve`、VS Code Live Server 等），访问对应地址即可。注意：直接 `file://` 双击打开时无法连接后端（CORS 拦截），会自动进入离线模式；要走在线模式请通过 HTTP 服务访问。

#### 3. 后台管理员账号

后端首次启动会自动创建一个管理员账号（若不存在）：

- 用户名：`admin`
- 密码：`admin123`

可用环境变量 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 覆盖。登录后头部会出现「后台管理」入口，或直接访问 <http://127.0.0.1:8080/admin.html>。

### 在线 / 离线如何切换

- **进入离线**：任意一次请求后端失败（网络错误 / `file://` 被 CORS 拦截）后，当前页面会话内不再尝试联网，自动使用本地存储；**刷新页面**后会重新尝试连接后端，可恢复在线。
- **业务错误不降级**：密码错误、用户名重复等后端返回的真实校验错误会原样提示，不会被误判为离线。
- 两种模式的账号、收藏、评价数据相互隔离，互不影响。

## 数据与账号说明

- 演示数据共 20 个景区（5A 8 个、4A 8 个、3A 4 个），景区等级与票价仅用于界面演示，请以贵州省文化和旅游部门的最新公告为准。
- **数据存储分两种模式**：
  - 在线模式：账号与登录会话保存在后端 MySQL（`tourism_database`，密码 BCrypt 哈希），清除浏览器数据不会删除账号；收藏与评价保存在当前浏览器的 `localStorage` 中。
  - 离线模式：账号、收藏、评价、景点数据全部保存在当前浏览器的 `localStorage` 中，首次运行自动播种内置景点与默认管理员（`admin` / `admin123`）。
  - 本地存储键：`qianxing_session_v1`（会话）、`qianxing_accounts_v1`（账号表，离线）、`qianxing_spots_v1`（景点，离线）、`qianxing_reviews_v1`（评价）、`qianxing_favorites_v1_<用户名>`（收藏）。清除浏览器数据会清空离线数据，在线数据不受影响。
- 评价规则：一个账号在一个景区最多保留一条评价，可随时修改或删除；星级为 1–5 整数，文字最多 200 字。展示评分 = 景区基础评分与本机评价的加权平均。
- 详情页每个景区另有 2 条内置「示例评价」（共 40 条），由项目作者依据景区公开资料撰写，仅用于演示评价区排版与交互；它们不是从高德地图等平台抓取的真实用户评论，也不计入评分，界面上以「示例」标签标注且只读。
- 景区评分为演示基准分。如需换成真实评分，可接入高德开放平台「地点搜索」接口返回的 `biz_ext.rating` 字段：需自行申请 Web 服务 Key，并建议通过后端代理调用，避免 Key 直接暴露在前端。
- 密码由后端使用 BCrypt 单向哈希存储，前端不保存明文密码；登录会话以服务端签发的随机 token 标识，后端可主动使会话失效。

## 数据层说明与扩展

`assets/js/store.js` 是前端统一数据层，向上对页面暴露一致的 API，向下根据后端可达性自动选择数据源：

- **在线**：后端地址为 `http://127.0.0.1:8081`（Spring Boot），账号 / 会话走 MySQL，收藏 / 评价走后端接口。
- **离线**：任意网络请求失败后降级到浏览器 `localStorage`，当前页面会话内不再联网，刷新后恢复在线尝试。
- 页面层只通过 `qz:authchange`、`qz:favchange`、`qz:reviewchange`、`qz:spotsloaded` 等事件感知数据变化，无需关心底层是在线还是离线。

如需更换数据源（例如把收藏 / 评价也迁到服务端、或替换为其他后端），只需在 `store.js` 中调整对应方法的实现，保持公开 API 与事件名不变，页面层无需修改。
